# Wiggle My Image Animator

A small, layperson-friendly web toy by Reactorcore: drop in a picture, it wiggles (a glfx.js swirl moving along a looping path), save it as a looping GIF or video and share it. Released as an HTML app on itch.io (https://reactorcore.itch.io/wiggle-my-image-animator), also downloadable as a zip that works offline via file://. MIT licensed. The project is finished and in maintenance; [checklist.md](checklist.md) is a short changelog plus any open items.

## Hard rules

- Plain HTML/CSS/JS only. No frameworks, no build step, no npm dependencies in the shipped app. Vendored libs go in `lib/` as classic `<script>` files.
- Must work from `file://`: no ES modules (`type="module"` is blocked there), no `fetch` of local files, and no loading local images into WebGL by URL (taints the canvas). That is why the sample pictures are embedded as data URIs in `lib/sample.js`.
- Keep it simple and playful (KISS). Agreed out of scope: two-image warp/flash transition, exports above ~720px.
- Palette lives as CSS variables at the top of `style.css` (lemon theme plus a dark block). Re-theme there, not inline.
- Never assume pricing in promo copy; free/tips/paid is the author's call.
- Markdown docs: never hard-wrap prose.

## Files

- `index.html` — markup only (plus an inline head script that sets the theme before first paint).
- `style.css` — palette variables, then layout/components. Phones (≤820px) stack the stage above the panel and size the stage to the picture's shape.
- `app.js` — all logic, sectioned with banner comments: tunables, slider mappings, state, frame maths, loading, render loop, saving, UI building, events, init.
- `lib/glfx.js` — glfx.js (MIT, Evan Wallace). Only `swirl` and `bulgePinch` are used.
- `lib/gifenc.js` — gifenc 1.0.3 (MIT, Matt DesLauriers): its CommonJS build wrapped in an IIFE exposing `window.gifenc`. To update, replace the code between the wrapper lines with the new `dist/gifenc.js`, minus the sourceMappingURL line.
- `lib/sample.js` — `window.SAMPLE_IMAGES`: the pictures in `assets/` as WebP data URIs (≤720px), one picked at random on start. Regenerate with `sh make_samples.sh` (needs ffmpeg) after changing `assets/`.
- `assets/lemon_mascot_1..6.png` — the author's own pictures (1 spiky lemon = the mascot, 2 shaggy monster, 3 pixel motorbike, 4 worm, 5 lemon face, 6 fuzzy cyclops), free to use in promo material. Not needed at runtime.
- `readme.md`, `guide.md` — shipped user docs (both end with the author's links block). `LICENSE` — MIT, shipped.
- `promo.md` — internal marketing notes and copypastas (itch.io, GitHub, YouTube), not shipped.
- `promo/` — `icon_og.png` (copy of the mascot), `screenshot_1..4.jpg` (1920×1080), `itch_thumbnail.jpg` (630×500), `cover.jpg` (1280×720). All but `icon_og.png` are generated by `testing/promo-shots.js`. Shipped in the download zip.
- `gifs/` — `demo.gif` and `demo_<style>.gif` for all 8 styles, for the itch page. Not shipped (keeps the zip small).
- `trailer/` — `trailer.md` (music analysis and shot list). The music mp3 and rendered mp4s are gitignored (the track's licence forbids distributing the file on its own).
- `testing/` — dev scripts, not shipped (see Testing).
- `build_release.bat` — release builder (see Releasing).
- `docs/For release prep/` — the author's reusable release-prep prompts.
- `old wip/` — old prototypes and early notes; gitignored, reference only.

## How it works (app.js)

- On load the picture is drawn into `source` (shrunk to ≤1440px long side). The frame is 720px on its long side, shaped like the picture but clamped between 1:2 and 2:1. The picture fills 80% of it (`IMAGE_FILL`), leaving room to wiggle.
- `composeFrame()` draws the picture on a transparent canvas, uploaded as a glfx texture once per picture (`rebuildTexture`), never per frame. Pictures upscaled ≥2× are drawn with smoothing off so pixel art stays crisp.
- The background colour goes under the effect (CSS background on `#stageFrame` in the preview), not into the texture: glfx fades pixels pulled from beyond the frame edge to transparent, so a baked background would show holes. Exporters fill the background first, then draw the glfx canvas on top.
- `effectAt(t, settings, W, H, z)` is the single source of truth for the effect at loop position t∈[0,1): `{kind:'swirl', x, y, radius, angle}` or `{kind:'bulge', x, y, radius, strength}`, scaled to any output size. It reads the current picture's globals (`frameW`, `imgRect`). `applyEffect(chain, e)` applies it to a glfx chain.
- Styles (`STYLES`) are closed sin/cos loops `path(a) → {u, v}` in −1..1, stretched over the picture by Wander, so every loop is seamless. The style button icons are drawn from the same functions.
- "Stay in frame" (`settings.fit`): `fitZoom(s)` returns one zoom for the whole loop, scaling picture, path and swirl radius together (the output is the unzoomed wiggle, zoomed about the centre). It forward-maps the picture's outline (`traceOutline`, edge cells of the alpha mask on a 64-cell grid) through `movePoint` at 64 loop positions (swirl is an exact rotation; bulge is inverted by bisection), then fits the bounding box with a 2% margin, zooming in up to 3×. Cached per picture/style/wiggle/wander.
- Backgrounds: see-through, white, black, green screen, magenta, plus a custom swatch (a native `<input type=color>` laid invisibly over a rainbow-ringed dot), stored as `settings.customBg`.
- The glfx canvas has `premultipliedAlpha:false` and no `preserveDrawingBuffer`, so read its pixels (`drawImage(fxCanvas)`) in the same task as `.update()`.
- Saving uses a second glfx canvas (`exportFx`) so it never disturbs the preview. `makeRenderer(s, W, H, bg)` uploads `composeFrame(W, H)` and its `draw(t)` paints background then effect onto a 2D canvas. Saves work from a settings snapshot; loading a new picture cancels a save in progress.
- GIF: `round(loop / 4cs)` frames at 4 cs each. ONE palette for the whole GIF, quantized with `rgb444` from 4 frames spread over the loop (the default `rgb565` took over a second per frame on photos). See-through uses `rgba4444` + `oneBitAlpha` and `dispose: 2` (hard edges).
- Video: MediaRecorder on `canvas.captureStream`, played in real time with rAF for whole loops lasting ≥3 s. Type = first supported entry in `VIDEO_TYPES` (MP4 first). See-through becomes white. Hiding the tab cancels recording.
- Share (Web Share API, shown when `navigator.canShare({files})`) shares the last GIF if `exportKey` still matches, else makes one first. If the tap's activation expired during the render, the button becomes "Ready! Tap to share".
- Keyboard: styles, backgrounds and sizes are radio groups (`radioKeys` + `syncRadios`: arrow keys, roving tabindex). The focusable stage frame peeks while Space is held. Rendering pauses while help is open.
- Settings persist in localStorage (`wiggle-settings-v1`), wrapped in try/catch. Light/dark via `:root[data-theme="dark"]`; the 🌙/☀️ button stores an explicit choice, `theme: null` follows the device live.
- Edge cases handled: HEIC (friendly message only after decoding fails, so Safari still works), animated GIF/WebP (first frame), EXIF rotation (browser), 1×1 and huge pictures, non-image files and pastes.

## Testing

All scripts drive the real app in headless Edge (`C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe`, SwiftShader WebGL) over file://. puppeteer-core is not part of the project; install it in a scratch directory and point NODE_PATH at it:

```
cd <scratch> && npm init -y && npm i puppeteer-core@23
NODE_PATH=<scratch>/node_modules node testing/browser-check.js <scratch>/shots
```

- `browser-check.js` — smoke test: styles, uploads from `assets/`, peek, help, desktop/phone/dark/light screenshots, prints console errors.
- `export-check.js` — presses the Save buttons for several picture/size/background cases, collects downloads into the output dir, tests Cancel. Inspect with `ffprobe -count_frames`. Headless SwiftShader records video at only ~18 fps.
- `promo-shots.js` (+ `promo-poster.html`) — rewrites `promo/` (except `icon_og.png`) and `gifs/`. The poster pulls the Fredoka font from Google Fonts.
- `trailer.js` (+ `trailer-layer.js`) — renders the YouTube trailer (`trailer/trailer.mp4`, 1920×1080) and with `--shorts` the 9:16 cut (`trailer/trailer_shorts.mp4`, 1080×1920, the app's phone layout). It fakes `requestAnimationFrame` and seeds `Math.random`, steps time at 30 fps, screenshots every frame and pipes them to ffmpeg with the music. `--draft` renders 480p, `--stills 1.5,9.4 --out <dir>` saves single frames. Beat times and scenes are in `trailer-layer.js`; card scenes draw extra pictures by swapping the app's picture globals around `effectAt`/`composeFrame` (`withPic`). Needs `trailer/Cafecito por la Manana - Cumbia Deli.mp3` locally.

Headless Edge reports dark mode by default; emulate `prefers-color-scheme` to check the other theme. ffmpeg is on PATH.

## Releasing

`build_release.bat` (copies an explicit file list, so new dev files never leak in) builds `dist/Wiggle-My-Image-Animator/` (app + readme, guide, LICENSE, promo), zips it as the offline download, and makes `dist/Wiggle-My-Image-Animator_itch-web.zip` with `index.html` at the top level for itch.io's HTML upload. It calls `%SystemRoot%\System32\tar.exe` explicitly, because Git's GNU tar ignores `-a` and writes a plain tar named `.zip`. After an app change: run `testing/browser-check.js`, rebuild, re-upload both zips to itch; regenerate `promo/` and the trailer only if the look changed.
